Integración opcional · LSFA 0.2 + Presentation 0.3

El agente pide.
El broker decide.

FastWebMCP conecta una tool del navegador con un broker LSFA confiable sin mostrar credenciales, PIN, TOTP ni otros secretos al agente.

Frontera importante: FastWebMCP no implementa LSFA, no captura secretos y no autoriza operaciones. Valida y transporta intención no sensible hacia el broker que inyecta la aplicación.

Flujo de autoridad

1 · AgenteEntrega destinatario, asunto u otra intención no sensible.
2 · FastWebMCPValida el schema y delega por la API imperativa.
3 · Broker LSFAAplica política, captura, riesgo, confirmación, expiración y ejecución.
4 · ResultadoDevuelve solo estado y comprobaciones sanitizadas, nunca valores capturados.

Uso mínimo

import { z } from 'zod';
import { registerLsfaTool } from 'fastwebmcp/lsfa';

registerLsfaTool({
  name: 'send_email_securely',
  description: 'Confirmar y enviar un correo.',
  inputSchema: z.object({ recipient: z.string().email(), subject: z.string().min(1) }),
  intent: {
    operation: 'send_email',
    purpose: 'Enviar solo después de confirmación local.',
    presentation: { profile: 'confirmation', locale: 'es-MX' },
  },
  broker: trustedBroker,
}, { exposedTo: ['https://agente-confiable.example'] });

trustedBroker es un adaptador del host LSFA creado por tu aplicación. No viene incluido porque el transporte y la política pertenecen al entorno confiable.

Qué garantiza cada capa

CapaResponsabilidad
WebMCPDescubrir e invocar la tool con argumentos no sensibles.
FastWebMCPValidar input, rechazar schemas secretos, preservar abort/origin/exposedTo y sanitizar resultados.
Broker LSFAPolítica, riesgo, campos, UI, confirmación, binding, expiración, consumo único y side effect.

Pruebas y límites

fastwebmcp/lsfa/testing incluye un broker simulado determinista. Solo registra solicitudes y devuelve resultados configurados explícitamente: no es autorización, no ejecuta acciones y no aporta garantías de producción.

La primera versión es transport-agnostic. HTTP loopback, Native Messaging y una extensión real quedan fuera hasta estabilizar el contrato público. Consulta las firmas completas en la referencia técnica.
